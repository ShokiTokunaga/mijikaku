# 記述の基準

## 記載内容を選ぶ

処理・項目と、その条件・値・結果を書く。失敗時の応答や保存結果も、根拠資料で確認できる範囲で明記する。再送や失敗時に更新が残らない場合は、その結果も明記する。

推敲では既存のフロントマターを保持する。原文に明記された仕様は、整理後の文書にも明記する。

「未記載は不実施」を適用したときの動作・条件・値・結果が変わらない範囲で、削除・書換を行う。

原則・既定動作の根拠は、文書や参照資料、使用する基盤の仕様・設定で確認する。

- 他で定めていない処理に「行わない」と付け足した部分は省く。
- 実行範囲、比較・設定・性質、原則や既定動作の例外は、削除で意味が変わる部分を残す。
- 実行する側の条件・値へまとめられるものは、意味を保って書き換える。
- 概要・表・手順で重なる仕様は、固有の条件・値・結果・参照先を保ってまとめる。フォーム表示と登録処理の権限など、同じ条件が複数の動作に掛かる場合は、どの動作に適用するかを明記する。

## 表現を整える

| 表現・構成 | 書き方・直し方 |
|---|---|
| 文末の否定形 | 行う側の条件・値で表せるか検討する。 |
| 文書の対象範囲 | 扱う操作が既に分かる場合は、対象外の列挙を省く。仕様の適用範囲を決める境界は残す。 |
| 否定を伴う対比 | 肯定側だけで伝わる場合は、否定側を省く。 |
| 補足の前置き | 不要な補足は文ごと省き、必要な条件・結果だけを本文へまとめる。 |
| 言い換えの前置き | 同じ情報を一度で伝える。 |
| 強調の前置き | 前置きを省き、条件や結果を直接書く。 |
| 説明・手順の予告 | 見出し・表・番号付き手順で分かる予告は省く。開始条件、固定順、優先順位がその文で初めて決まる場合は残す。区別に必要な対象名は見出し・項目名にする。 |
| 例示 | 定義済みの範囲や式を当てはめただけの例は省く。受け付ける表記や例外を初めて示す部分は残す。 |
| 括弧書き | 名称と識別子の対応は初出か定義箇所にまとめ、既出の説明・例示を省く。必要な条件は本文へ移し、単位・略称・画面部品名・識別子の併記には括弧を使える。 |
| 長い可能表現 | 可否・権限は「できる／できない」に縮め、実行動作と分かる場合は「する」で書く。画面の固定文言は表記を保つ。 |
| 語の重なり・同文の繰り返し | 語や定義の重複を省き、一か所にまとめる。 |
| 長い段落 | 短縮したうえで、話題ごとに分ける。 |

## 長文を分ける

削れる部分を詰めた後、残った文を一文ずつ追えるようにする。分けた後も、条件がどの文に掛かるかと、処理の順序が分かるようにする。

箇条書きは一項目一文を目安にする。条件を満たす場合と「それ以外」など、並列の文は同じ階層に並べる。先の文の内訳や詳細はその文の子項目にする。

```markdown
- 取込前にファイル形式を検査する。ヘッダは列名・順序・大文字と小文字が指定どおりか確認する。データ行数が1件以上500件以下か確認する。
```

```markdown
- 取込前にファイル形式を検査する。
    - ヘッダは列名・順序・大文字と小文字が指定どおりか確認する。
    - データ行数が1件以上500件以下か確認する。
```

表セルに異なる項目が詰まっているときは列や行に分ける。長い説明は表の外に置く。同じセルに複数の文を残す場合は、表示環境で使える `<br>` などで文ごとに表示を改行する。

```markdown
| 条件 | 画面の応答 |
|---|---|
| 入力形式エラー | 入力画面を再表示する。<br>送信した入力値をすべて保持する。<br>該当する各入力欄の下に、検査で見つかった理由を表示する。 |
```

## 長さの目安

次のいずれかに当たる箇所は、短縮・分割を検討する。

| 単位 | 文字数のみ | 文字数と文数の組合せ |
|---|---:|---|
| 段落 | 240字超 | 60字以上かつ4文以上 |
| 表セル | 120字超 | 60字以上かつ3文以上 |
| 箇条書き項目 | 160字超 | 60字以上かつ3文以上 |

文字数は空白を除く表示文の長さ、文数は句点などの区切りによる概数。
